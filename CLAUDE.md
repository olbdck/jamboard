# JamBoard: notes for Claude

- Communicate with Oleh in Ukrainian. Original design (no FigJam copies); Orbit Pro look, raspberry accent (#c2185b / #ff6b9d), WCAG AA text, light/dark/auto themes. Top quality goal: maximum smoothness of animation, actions and controls.
- Everything is one file, `index.html` (vanilla JS, no build). `config.js` holds the Supabase URL + publishable key (safe to commit; never a secret/service_role key).
- Hosting: GitHub Pages from `main` root (https://olbdck.github.io/jamboard/). The claude.ai artifact copy is frozen at v10; don't update it.
- Data: Supabase table `docs(path, coll, data jsonb)` — a tiny document store. Board items live at `boards/<bid>/items/<id>`, board meta at `boards/<bid>`. (The old `main` board on `items/…`, `board/meta` exists only in local mode now.) Every write carries `rev`; older revs are ignored. New item types/fields need **no** database change; only auth, access rules or limits do (then add SQL to `supabase/schema.sql` and ask Oleh to run it).
- Private boards (`supabase/private-boards.sql`): a board opens only by its link. Ids are 24 random chars (`newBoardId()`; server accepts 20–64). The browser can't touch `docs` directly: only RPC `jb_get(p_path)`, `jb_list(p_coll)`, `jb_put(p_path, p_data)`, `jb_del(p_path)`, which accept paths inside one board. Live updates: a DB trigger calls `realtime.send` on topic `jb:<bid>` (event `row`, {path, data} | {path, gone} | {path, big}); presence rides the same per-board channel. «Мої дошки» = localStorage `jamboard:myboards` (created or opened). Never add a query that lists boards from the browser.
- `startSupabase()` in index.html shims the claude.ai `db`/`room`/`assets` API on Supabase: RPC load first, the board's broadcast channel for live updates, 2 s polling if realtime fails; presence on the same per-board channel. Without config it runs local-only.
- Item types: sticky, image, section, stamp, comment, text, link (rope: a, b, label, color, flow, dash, thick), web (link card: url, yt, title, desc, site, img, icon), node (diagram block: text, shape rect|round|pill|circle|diamond|cyl|hex, icon service|db|cache|queue|api|user|web|mobile|cloud|storage|fn|lock|mail|none, color). board (a card linking another JamBoard board: bid, title snapshot; made by pasting a `…#b=<id>` link of this site, or by the MCP from such a `web` url): shows that board's cover, opens in a new tab via its link, and «Переглянути» opens `openPeek()`, a centred read-only preview (items fetched once with `peekItems`, drawn by `peekBuild`, pan/zoom) with «Закрити» and «Перейти в дошку». `peekBoard(id)` reads meta + cover once and is shared with the gallery. A rope between two nodes is an elbow wire with an arrow (no arrow when flow:false): the `Route` module (`// <route>` … `// </route>`, index.html only) finds right-angle paths around all cards (A* on a sparse grid of lines around blocks and gaps), gives wires sharing a block side their own ports, spreads parallel runs into lanes, and on each `renderLinks` reroutes only wires touching or crossing a box that changed. Hovering (140 ms delay) or selecting a card lights up its links and fades the rest by stroke colour (never group opacity: it drops frames while dragging).
- Mermaid flowcharts: the `Flow` module (parser + layered auto-layout, `// <flow>` … `// </flow>`) is copied verbatim into index.html and the MCP index.ts; keep both copies identical. Toolbar: D = block tool, M = Mermaid dialog; pasting flowchart text onto the canvas also builds it. Subgraphs become sections (nested ones fold into the outermost). Values from others are set via textContent; only https:// links.
- The cloud container can't reach supabase.co or cdn.jsdelivr.net: test with Playwright and a mocked `window.supabase`, and say real-backend checks need Oleh's browser.
- Sections: cards remember their section in `sec` (set on drop, wrap, section draw/resize); overlapping sections never take each other's cards. Stamps/pins and legacy cards fall back to geometry (smallest containing section).
- «Мої дошки» is a gallery popup (`#boardMenu`, `galBuild`/`openGallery`): cards with a cover, title, author (`by` in board meta) and who is there now. Covers: doc `boards/<bid>/cover/v1` = { v:1, w, h, n, s:[[kind,x,y,w,h,…]] } in a 0..1000 box (`makeCover`/`coverSvg`), written by whoever edits (the lowest peer id for remote changes), cached in localStorage `jamboard:cover:<bid>`; a missing or `{v:0, stale}` cover (the MCP marks it stale after edits) is rebuilt from items. Presence on other boards: `room.watchBoard(bid)` subscribes to `jb:<bid>` without tracking (invisible there), only for ids already in the local list; tracked presence carries {n, e, c}.
- Shared timer per board: doc `boards/<bid>/timer/state` = { dur, run, end } | { dur, left } | { dur } (epoch ms).
- MCP server: `supabase/functions/jamboard-mcp/index.ts` (Supabase Edge Function, no deps, stateless JSON-RPC; also runs under Node for tests). Auth: `?key=` = secret `JAMBOARD_MCP_KEY`; DB key from `JAMBOARD_DB_KEY` or the default service-role env. Keep its item shapes in sync with index.html when adding item types.
- `config.js` `defaultBoard` = public demo board «Знайомство з JamBoard» (id 7JnHshrp8cN4tGnQKPoY2Ifp, formerly budslw073hv) where new visitors land. It is pinned first in «Мої дошки» (✦, no ×) and is view-only: `viewOnly()` (demo, or board meta `ro: true`) adds `body.view-only`, which hides every editing control, makes any drag pan, and blocks keys, paste, drop and writes. The server enforces it via `supabase/readonly-boards.sql` (jb_put/jb_del refuse ro boards except `cover/v1`; the browser can never set `ro`); the MCP still edits it. The JamBoard logo button (`#boardsBtn`) opens the boards gallery. There is no «Очистити» button. Timer chip and Share button live in the top-right people panel; timer digits use the vendored DSEG7 font (fonts/, OFL).
- The jamboard MCP may be connected to Claude sessions (mcp__jamboard__*): use it to read/edit live boards.
- Security: no secrets in git (only the publishable key). `supabase/security.sql` caps browser deletes/updates at 20 rows per request, copies every deleted row to `docs_trash` (hidden from anon), and checks path format and 1 MB per doc. Writes by item must stay single-row from the browser; bulk writes go through the MCP (service role). The MCP needs an explicit `board` (no `main` default).
- Paste ripple: after a paste (`ripArmed`, consumed by the next `commit` with new ids) the grid dots around the new objects light up in a raspberry wave from a drop (`rippleAt`/`ripStep`). Drawn on a small `#ripple` canvas over just that patch (dots bucketed by alpha into 8 paths per frame), panning only moves it, a zoom change ends it; reduced motion = a plain fade. View-only boards never paste, so never ripple.
