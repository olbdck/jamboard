# JamBoard

Спільна дошка для команди: стікери, секції, текст, мотузки між картками, штампи, коментарі, картки-посилання з превʼю, схеми, таймлайни з діаграмою Ганта (смуги задач із прогресом і залежностями), таблиці й матриці (картки стають у ряд, скільки вміщує колонка), картки задач, шаблони ретро, голосування крапками, приховане писання й експорт у Markdown.
Один файл `index.html`, без збірки.

## Запуск на GitHub Pages + Supabase

1. **Supabase.** Створіть проєкт на https://supabase.com (безкоштовний план).
   - Відкрийте SQL Editor і виконайте `supabase/schema.sql`. Це створить таблицю дошок, увімкне realtime і створить сховище картинок.
   - Потім виконайте `supabase/security.sql`: обмеження на масове видалення чи перезапис, кошик видалених записів (`docs_trash`, з нього можна все відновити), ліміти розміру.
   - І нарешті `supabase/private-boards.sql`: дошки стають приватними за посиланням (див. нижче).
2. **Ключі.** У Project Settings → API скопіюйте `Project URL` і публічний `anon` ключ. Вставте їх у `config.js` (зразок у `config.example.js`):
   ```js
   window.JAMBOARD_CONFIG = { supabaseUrl: 'https://xxxx.supabase.co', supabaseAnonKey: '...', bucket: 'jamboard' };
   ```
   `anon` ключ публічний, його можна комітити. **Ніколи не вставляйте сюди `service_role` ключ.**
3. **GitHub Pages.** Settings → Pages → Deploy from a branch → `main` / root. Дошка буде за адресою `https://<user>.github.io/<repo>/`.
   Поділитися конкретною дошкою: кнопка «Поділитися» дає посилання з `#b=<id>`.
   У `config.js` можна вказати `defaultBoard`: публічну дошку, на яку потрапляють нові відвідувачі.

Без `config.js` (або з `null`) дошка працює лише локально в браузері.

## Керування дошкою з Claude (MCP)

`supabase/functions/jamboard-mcp/index.ts` — MCP-сервер: Claude читає дошки, додає стікери, секції, текст, мотузки й картки-посилання, змінює й видаляє їх, керує таймером.

1. Supabase → Edge Functions → **Deploy a new function → Via Editor**. Назва `jamboard-mcp`, вставте вміст `index.ts`, Deploy.
2. У налаштуваннях функції вимкніть **Verify JWT** (Enforce JWT verification).
3. Edge Functions → **Secrets** → додайте `JAMBOARD_MCP_KEY` = довгий випадковий рядок (це пароль до MCP).
4. Claude → Settings → Connectors → **Add custom connector**, URL:
   `https://<project>.supabase.co/functions/v1/jamboard-mcp?key=<JAMBOARD_MCP_KEY>`

Інструменти (MCP бачить усі дошки, бо працює з service role; `board` обов'язковий): `list_boards`, `get_board`, `add_items` (стікери, текст, секції, мотузки, картки-посилання, штампи, коментарі, таймлайни, таблиці й матриці, картки задач, смуги Ганта `bar` зі `start`/`due`/`progress`/`after`; картку можна одразу покласти в клітинку: `grid` + `column` + `lane`), `update_items`, `delete_items`, `add_mermaid`, `create_board`, `add_template` (спринти, діаграма Ганта, роадмап, матриця, ретро), `voting` (голосування крапками: старт, підсумки, сортування), `hidden_writing` (приховане писання), `export_markdown`, `sync_tasks` (оновити задачі з GitHub; Jira й Linear заповнює агент), `timer`.
У новому проєкті Supabase таблиці треба явно дати доступ ролям (див. `grant` у `schema.sql`), зокрема `service_role` для MCP.
Зміни з’являються на відкритих дошках одразу.

## Приватність: дошка відкривається лише за посиланням

- id дошки це 24 випадкові символи (близько 142 біт), підібрати його неможливо.
- Браузер не має прямого доступу до таблиці `docs`. Він читає й пише лише через функції `jb_get`, `jb_list`, `jb_put`, `jb_del`, які приймають шлях усередині однієї дошки (`boards/<id>/…`). Переглянути список дошок нікому не можна.
- Живі оновлення йдуть каналом самої дошки `jb:<id>` (база розсилає зміни через `realtime.send`, тож правки з MCP теж приходять наживо). Присутність теж окрема на кожну дошку.
- Бакет картинок віддає файли за прямим посиланням, але список файлів не читається.
- «Мої дошки» це дошки, які цей браузер створив або відкривав за посиланням (localStorage). Хрестик прибирає дошку зі списку, але не видаляє її.
- Хто має посилання, той може редагувати дошку. Режиму «лише перегляд» поки немає.

`private-boards.sql` також переносить старі дошки (стара `main` і короткі id) на нові випадкові id, а старі рядки прибирає (вони лишаються в `docs_trash`). Останній запит скрипта показує нові посилання. Таблиця `jb_moved` зберігає відповідність старих і нових id і доступна лише з дашборда.
